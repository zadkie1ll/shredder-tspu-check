# shredder-tspu-check

Отдельный сервис мониторинга доступности активных Remnawave-нод. Текущий
этап использует Check-Host как предварительный транспортный сигнал. Он не
меняет DNS, IP-адреса, конфигурацию Remnawave или состояние нод.

Check-Host используется как бесплатный частый baseline. Если российские
точки дают timeout, а внешние подтверждают доступность ноды, сервис запускает
платный приватный RIPE Atlas `sslcert`-замер к IP с клиентским Reality SNI.
SNI и порт автоматически читаются из `configProfile.activeInbounds` Remnawave.
Без подтверждения Atlas тревога о блокировке не отправляется.

## Как формируется текущий вердикт

Для каждой активной ноды сервис запускает TCP-проверку `IP:порт`, ждёт
динамические результаты Check-Host и разделяет точки на две группы:

- российские точки `CHECKHOST_RU_TARGETS`;
- внешние контрольные точки `CHECKHOST_CONTROL_TARGETS`.

Возможны три результата:

- `clean` — хотя бы одна российская точка достигла IP;
- `blocked` — все ответившие российские точки получили явный timeout, а хотя
  бы одна внешняя контрольная точка достигла IP;
- `uncertain` — недостаточно данных, отсутствует нужная география либо сервер
  одновременно недоступен из России и извне.

`Connection refused` подтверждает доступность IP и не считается блокировкой.
`Open or filtered`, отсутствующий результат и неизвестные ошибки не
превращаются в timeout автоматически.

## Уведомления

- первый успешный `clean` создаёт тихий baseline;
- `clean → blocked` отправляет тревогу;
- `blocked → clean` отправляет восстановление;
- `uncertain` не стирает последний достоверный статус;
- состояние уведомления записывается только после успешного ответа Telegram;
- недоставленная тревога повторяется при следующем подтверждённом цикле.

Проверки нод выполняются параллельно с лимитом `CHECK_CONCURRENCY`.

## Запуск

```bash
cp .env.example .env
mkdir -p data
docker compose up -d --build
docker compose logs -f
```

Для одноразового диагностического запуска задайте `RUN_ONCE=true`. Сервис
выполнит один цикл и завершится. Для Remnawave v3 нужен отдельный API key со
scope `nodes:read`.

Для Telegram-топика используются `TELEGRAM_CHAT_ID` и
`TELEGRAM_MESSAGE_THREAD_ID`. Для ссылки вида
`https://t.me/c/3780243318/2815/2816` это `-1003780243318` и `2815`.

## Проверка

Тесты не обращаются к Remnawave, Check-Host или Telegram:

```bash
python -m unittest discover -s tests -v
```

## Граница безопасности

В сервисе отсутствуют операции изменения Remnawave, Cloudflare и сетевых
интерфейсов. Автоматическая замена IP будет реализовываться отдельным этапом,
сначала только в dry-run и с ручным подтверждением.
