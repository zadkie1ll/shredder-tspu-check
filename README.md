# shredder-tspu-check

Отдельный сервис мониторинга доступности активных Remnawave-нод. Для каждой
ноды он напрямую запускает приватный RIPE Atlas `sslcert`-замер к IP с тем же
Reality SNI и портом, которые получают клиенты. Check-Host не участвует ни в
запуске, ни в вердикте. SNI и порт автоматически читаются из
`configProfile.activeInbounds` Remnawave.

## Как формируется текущий вердикт

Наборы российских probes и алгоритм совпадают с Monkey Island:

- лёгкий режим — 10 probes в семи сетях операторов, около 200 кредитов;
- полный режим — 33 probes в двенадцати ASN, около 660 кредитов;
- используются только подключённые в момент запуска probes;
- сбор продолжается до ответа всего назначенного набора либо четыре минуты;
- TLS считается достигнутым при наличии `cert`, `method` или `alert`;
- место обрыва классифицируется как `tcp_fail`, `tcp_refused`, `tls_fail`
  или `unknown`.

Возможны три результата:

- `blocked` — TLS-доступность 50% и ниже;
- `clean` — TLS-доступность 70% и выше;
- `uncertain` — между 50% и 70% либо ответило слишком мало probes.

По умолчанию используется лёгкий режим (`RIPE_ATLAS_LIGHT_MODE=true`) с
интервалом один час. Для ручной глубокой диагностики можно временно включить
полный режим. `RIPE_ATLAS_DAILY_BUDGET` не позволяет случайно выйти за
заданный суточный расход.

## Уведомления

- первый успешный `clean` создаёт тихий baseline;
- `clean → blocked` отправляет тревогу;
- `blocked → clean` отправляет восстановление;
- `uncertain` не стирает последний достоверный статус;
- состояние уведомления записывается только после успешного ответа Telegram;
- недоставленная тревога повторяется при следующем подтверждённом цикле.

Проверки нод выполняются параллельно с лимитом `CHECK_CONCURRENCY`.

## Запуск

```bash
cp .env.example .env
mkdir -p data
docker compose up -d --build
docker compose logs -f
```

Для одноразового диагностического запуска задайте `RUN_ONCE=true`. Сервис
выполнит один цикл и завершится. Для Remnawave v3 нужен отдельный API key со
scope `nodes:read`.

Для Telegram-топика используются `TELEGRAM_CHAT_ID` и
`TELEGRAM_MESSAGE_THREAD_ID`. Для ссылки вида
`https://t.me/c/3780243318/2815/2816` это `-1003780243318` и `2815`.

## Проверка

Тесты не обращаются к Remnawave, RIPE Atlas или Telegram:

```bash
python -m unittest discover -s tests -v
```

## Граница безопасности

В сервисе отсутствуют операции изменения Remnawave, Cloudflare и сетевых
интерфейсов. Автоматическая замена IP будет реализовываться отдельным этапом,
сначала только в dry-run и с ручным подтверждением.
